# Security

Report vulnerabilities privately through GitHub's security advisory reporting for this repository. Do not put keys, tokens, resume contents or service account JSON in public issues.

The previously tracked `private_key.pem`, certificate and CSR have been removed from the current tree. Historical commits still contain the old private key: consider it compromised, revoke/rotate any certificate or deployment credential that used it. No history rewrite is performed. Removing a file does not revoke the key.

Use a unique random `SESSION_SECRET` of at least 32 characters. Firebase Admin initializes only when needed, from `FIREBASE_SERVICE_ACCOUNT_JSON` or ADC. Give its service account the minimum necessary Firestore and Firebase Auth permissions. End users must not have direct access to `sessions`, `webSessions`, question answer keys or another user's progress. Configure Firestore rules independently; Admin SDK bypasses rules. Never expose a service account to browser code. The browser Firebase web configuration is public project metadata, not an Admin private key.

Deploy behind HTTPS. Production cookies are Secure, HttpOnly and SameSite=Lax. Set `TRUST_PROXY=true` only behind exactly one trusted proxy and prevent direct public access to the app port. Cookie-authenticated mutation requests with cross-site Fetch Metadata or foreign Origin are rejected. Bearer clients must protect their tokens. Logout clears local cookies; it does not globally revoke a Firebase identity.

Production sessions use Firestore `webSessions`; enable a TTL policy on `expiresAt` to clean up expired records. Development uses a process-local session store. Avoid logging prompts, resumes, authorization headers, cookies or provider error bodies. PDF/DOCX uploads are limited to 5 MiB; JSON/forms to 256 KiB. Files are parsed in memory and no submitted code is executed on the host. For hostile public deployments add edge rate limiting and isolate document parsers/Chromium under resource limits.

Resume PDFs are produced from escaped EJS data with browser JavaScript disabled and all resource requests blocked. Chromium closes in a `finally` block on success and failure. `CHROMIUM_NO_SANDBOX=true` is an explicit opt-in for isolated containers; prefer an enabled browser sandbox when the host supports it. Mock test completion and report writes are transactional, ownership is checked and answers are withheld until grading.

Tests delete credential-related environment variables before importing application modules, inject Firebase/Gemini doubles and never contact the live services. Run `npm ci`, `npm run check`, and `npm audit` regularly; read the actual audit report rather than applying breaking automatic downgrades.

## Product access boundaries

Question management requires a boolean `admin: true` claim in a verified, revocation-checked Firebase token. A client role field or an admin-looking UID grants no permission. Edits/archive operations require current revisions and write audit metadata. Answer keys and explanations are omitted from learner question cards.

The new product collections are backend-only: `questionBank`, `questionEvents`, `interviewSessions`, `users/{uid}/bookmarks`, and `users/{uid}/studyGoals`. Apply explicit restrictions in the deployed Firestore rules and remove any overlapping broad client allow rules; a `false` rule does not override another permissive matching rule. Backend checks do not protect against direct Firestore access if the project rules remain permissive. Existing project rules were not read or deployed by this coding task. Review these boundaries with your authorized Firebase operator before exposing a live deployment.

Persistent interview snapshots contain private grading rubrics. Only the verified owner may use the session APIs, even when the caller is an administrator. Sequential answers are protected by an expiring evaluation lease, request replay checks and atomic completion/report writes. Never log candidate answer bodies or SDK credentials. Archived questions remain in previously authorized session snapshots so completed reviews remain reproducible.

Study goals and analytics are scoped under the authenticated UID; request body/query UID fields never select another user's data. Rendering uses text nodes for user/model content. Progress calculations only normalize known score scales and disclose their bounded recent-attempt window. Production credential binding, index deployment and live rules enforcement need separate deployment validation; no live secrets or personal histories are shipped in test/sample fixtures.

Coding practice treats source code as private untrusted text. It is never executed. The execution endpoint returns 501 and cannot be enabled by an environment flag; no runner integration is shipped. AI feedback/estimate fields remain separate from executable results, which are explicitly unavailable. Owner-scoped draft/submission records and revision/lease transactions must not be weakened when adding a runner. Use an independently isolated runner with authenticated result provenance and strict resource/network limits in a future reviewed change. Dev-tooling advisory status and the remaining unpatched watcher chain are documented in `docs/DEPENDENCIES.md`.

The offline demo is a separate loopback-only entry point with synthetic memory storage and expiring opaque demo tokens. Production has no demo-auth switch; demo tokens must never be accepted as Firebase tokens. Demo learners have no admin claim and use the normal backend owner checks. Live bindings are not read, replaced or loaded from .env. Same-origin mutation checks, a self-only network CSP, route restrictions and host/peer loopback checks remain required. Do not deploy this volatile local demo as a public sandbox. Use synthetic input only; exit/restart clears demo data. See docs/DEMO.md for the trust boundary and explicitly pending live/deployment validation.

React migration retains server-side cookie/session ownership, revocation and CSRF boundaries. Firebase browser auth uses in-memory persistence; no token is stored in localStorage or a VITE variable. `/api/runtime` exposes only existing publishable Firebase web settings and rejects unexpected config fields. React report/result HTML comes only from server-sanitized handlers. Demo cookies/adapters remain separate from production and cannot enable a production auth bypass. Optional speech recognition is user initiated, has a typing fallback and may use the browser vendor's service; no audio upload/execution service is added.
